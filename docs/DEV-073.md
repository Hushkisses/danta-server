# DEV-073 — Army commander assignment / movement

Status: IMPLEMENTED — Windows automated verification pending

## Execution-plan basis
DEV-073 is 군단 지휘관 배치/이동. It is not the general-equipment ticket.

## Implemented
- ArmyState can optionally reference one commander general ID.
- GameState can resolve which army currently carries a given general.
- ArmyCommanderService supports assign, move between armies, and unassign.
- General and army must belong to the same nation.
- A general may command at most one army and an army may have at most one commander.
- Commander reassignment/removal requires stationed armies.
- Direct army-to-army commander movement requires both armies to be stationed at the same strategic point.
- When an army itself moves, its commander remains attached to that army; no separate teleport/movement state is invented.

## Deliberately unresolved
The source material does not define a separate travel time/cost for an unassigned general moving independently between points. DEV-073 therefore does not invent independent general teleportation, travel queues or travel duration.

## Persistence boundary
ArmySnapshot is not changed in this ticket because general persistence itself is still an explicit open item. Persisting a commander ID without the referenced general would create a partial/invalid restore model. Commander/general snapshot integration must be added together, preserving old snapshot compatibility, when generals become persistent season state.

## Automated tests
Tests cover friendly assignment, enemy rejection, duplicate assignment prevention, co-location requirement and commander retention while the army moves.

## Windows verification
Stop Paper, pull main, run dev-server\\quick-deploy.bat, then start dev-server\\start-dev.bat after all tests/build/deploy succeed. No player command is introduced by this core-only ticket.
