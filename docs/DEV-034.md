# DEV-034 — Sequential operation queue

Status: COMPLETE — Windows build and Paper live-server verification passed

## Goal
Allow a stationed army to reserve an explicit adjacent route such as A -> B -> C and automatically start the next leg after each arrival. This implements the execution-plan completion condition “A→B→C 예약 진행”.

## Implemented
- `ArmyOperationQueue` and `ArmyOperationQueueService` in core.
- The full explicit route is validated before the first leg starts; every leg must connect adjacent strategic points.
- `/danta army queue <army-id> <destination1> [destination2 ...]` starts a sequential operation.
- `/danta army queue-show <army-id>` shows remaining destinations in Korean.
- DEV-033 remains the one-leg execution primitive. On arrival, DEV-034 advances the queue and schedules the next leg.
- Snapshot schema v7 persists remaining operation destinations; schemas v1-v6 remain readable.
- Restart restores both the current DEV-033 movement and the remaining DEV-034 route.
- Queue validation errors exposed to players are localized in Korean.

## Scope boundary
- DEV-034 accepts explicit waypoints. Automatic shortest/safe/stealth route finding from the broader design is a later expansion and is not invented into this ticket.
- DEV-035 will add automatic stop conditions for combat, major points, supply, and related events.
- Queue depth is not arbitrarily capped here because v0.3 does not provide a final numeric maximum.
