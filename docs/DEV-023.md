# DEV-023 — Territory / Ownership Change

## Goal
Make strategic-point ownership changes authoritative, validated, event-driven, and immediately persisted.

## Implemented
- `TerritoryService` is now the authoritative boundary for strategic-point ownership changes.
- Validates the target point and the new owner nation.
- No-op ownership assignments do not emit duplicate events.
- Emits `StrategicPointOwnershipChangedEvent` after a real ownership change.
- Paper adapter subscribes to the event, logs the transfer, and immediately flushes a snapshot.
- Existing `/danta point owner <point> <nation|none>` now uses `TerritoryService` rather than mutating the point directly.
- `/danta nation capital` now rejects non-existent strategic point IDs, preventing dangling capital references.

## Validation
Core test verifies:
- neutral -> red ownership change
- duplicate assignment produces no duplicate event
- red -> blue transfer
- invalid nation is rejected

Result: `DEV-023 core test: PASS`

## Notes
Combat-driven capture will call the same `TerritoryService` from DEV-044 onward, so admin commands and battle capture share one ownership/event path.
