# DEV-062 — Morale / retreat / pursuit

Status: COMPLETE — Windows automated tests/build and Paper boot verified

## Design basis
Design v0.3 defines:
- morale stages: inspired / high / normal / low / near-collapse;
- most defeats as routs rather than annihilation;
- cavalry as valuable for pursuit;
- blocked retreat, isolation and pursuit as factors that increase permanent loss;
- supply shortage/depletion as a later source of morale/retreat/loss penalties.

The execution plan assigns morale/retreat/pursuit to DEV-062 and supply/isolation/retreat-route handling to DEV-064.

## Implemented
- MoraleState introduces the five authoritative design stages.
- RetreatPursuitContext carries explicit morale state for both sides.
- MoraleRetreatPursuitPolicy reuses DEV-042 CombatLossPolicy instead of duplicating casualty rules.
- A defeated side is explicitly represented as routed when the existing loss result requires retreat.
- Winning cavalry receives an explicit pursuit-advantage flag against a routed opponent.
- CombatResolutionV1 combines staged combat, existing provisional casualty results, and morale/rout/pursuit diagnostics.
- No numeric morale multiplier or extra pursuit casualty rate is invented because v0.3 does not fix those values.

## Scope boundary
- DEV-042 provisional casualty rates remain 10% winner / 25% loser / 10% draw until balancing replaces them.
- DEV-062 does not make morale stages alter combat power with arbitrary coefficients.
- DEV-062 does not add arbitrary extra casualties for cavalry pursuit.
- Retreat-route blocking, isolation and supply shortage effects belong to DEV-064.
- Permanent-loss / wounded / deserter split remains future work because v0.3 specifies the categories but not their numeric split.
- Commander morale/pursuit modifiers belong to DEV-070+.

## Automated tests
Tests cover the five morale stages, rout survival, cavalry pursuit advantage, absence of invented non-cavalry pursuit bonus, morale-state transport without unfixed numeric effects, and draw behavior.
