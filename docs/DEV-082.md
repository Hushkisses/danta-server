# DEV-082 — Facility world appearance sync

Status: IMPLEMENTED — Windows quick-deploy/Paper/live NBT verification pending.

## Goal
Synchronize authoritative FacilityService state to Minecraft world appearance using vanilla/Paper Structure NBT templates.

## Confirmed design
- Core facility state remains authoritative. A missing visual never removes or rolls back a facility.
- Runtime structure format is vanilla Structure NBT; no WorldEdit/FAWE runtime dependency.
- Template key: `danta:facilities/<facility-id>/tier_i|tier_ii|tier_iii`.
- Paper resolves this under the primary world structure directory.
- Facility completion/upgrade queues visual sync immediately.
- Snapshot restore queues all installed facilities for visual reconciliation.
- Visual sync never force-loads a chunk. If the target chunk is unloaded, it remains pending and ChunkLoadEvent retries it.
- Missing NBT is non-fatal and remains pending.
- Entities in templates are not spawned by facility appearance sync.

## Provisional layout
Until final strategic-map facility-slot anchors are authored, slot origins use a provisional grid:
- point anchor + (8, 0, 8)
- 16-block spacing
- four columns per row

These values are implementation placeholders, not final map/balance content. Final map slot metadata can replace this without changing FacilityService.

## NBT authoring contract
For a facility whose ID is `farm`, Structure Block names are:
- `danta:facilities/farm/tier_i`
- `danta:facilities/farm/tier_ii`
- `danta:facilities/farm/tier_iii`

Tier templates for the same facility should use the same origin and the same saved bounding-box size. Air inside the template canvas is intentional: it lets a higher/lower visual replace blocks from the previous tier without a separate destructive world-clear pass.

## Verification commands
- `/danta facility visual-status`
- `/danta facility visual-sync <point-id> <facility-id>`

Player/admin-facing results are Korean; internal IDs remain English.
