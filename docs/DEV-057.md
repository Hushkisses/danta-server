# DEV-057 — Overextension / administrative demand v0

Status: IMPLEMENTED — awaiting Windows automated + Paper verification

## Design basis
v0.3 defines base administrative capacity around 6; point demand is normal 1, important-normal/port 1.25, major 2, with capital handled separately. Capacity excess should hurt revenue/integration/recovery/NPC stability while avoiding an artificial direct combat-power penalty. The exact progressive formula is explicitly not final.

## Minimal implementation
- AdministrativeCapacityService derives status from current point ownership; no duplicate persisted state.
- Base capacity: 6.0.
- Demand: CAPITAL 0 in v0 (separate treatment deferred), PORT 1.25, MAJOR 2.0, other current point types 1.0.
- Provisional revenue penalty: -10 percentage points per excess demand, floor 50%.
- Penalty currently applies only to strategic-point GOLD production because tax/revenue is the only v0.3-listed affected system already implemented.
- Strategic resource production and combat power are not reduced.
- /danta economy admin <nation-id> shows owned points, demand/capacity, overextension and revenue efficiency in Korean.

## Scope boundary
Integration progress, repair/recovery and NPC stability are not implemented yet, so DEV-057 exposes a reusable status/multiplier for those future systems rather than inventing placeholder subsystems. Exact progressive formula remains a balancing target.

## Verification
quick-deploy automated tests must pass. Paper test should compare a nation below capacity and above capacity with /danta economy admin, then verify a gold-producing EconomyTick uses the displayed revenue efficiency.
