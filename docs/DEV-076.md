# DEV-076 — Initial general data (~10)

Status: PARTIAL / DEV-076A VERIFIED — Windows automated tests/build and Paper boot verified; actual initial roster intentionally unresolved

## Source basis
Execution plan v1.0 assigns DEV-076 to approximately 10 initial generals and requires content to be data-driven via YAML/JSON. Design v0.3 establishes the general grade/level/stat/trait/ability structure, but does not provide authoritative names and final per-general balance values for the initial roster.

## DEV-076A implemented
- YAML-based GeneralDefinition schema.
- Strict GeneralCatalogLoader.
- Fields: internal id, player display name, grade, level, four stats, 0-2 base traits, 0-1 unique ability.
- Duplicate IDs, unknown fields, invalid grades/levels/stats and invalid trait/ability cardinality are rejected.
- UTF-8 Korean display names are supported.
- Shipped resource: generals/initial-generals.yml.
- The shipped roster is deliberately empty until content approval.

## Why the catalog is empty
Inventing ten names and their grades/stats/traits/abilities would turn unresolved game content/balance into accidental source-of-truth values. DEV-076 is therefore NOT COMPLETE after DEV-076A. The representative should approve a roster proposal before those entries are committed.

## Still required for DEV-076 completion
- approve approximately 10 initial general identities/display names;
- approve grade distribution;
- approve initial level/stat values or a generation rule;
- approve each general's 0-2 base traits and optional unique ability;
- decide initial ownership/acquisition placement if these generals should enter GameState at season bootstrap rather than merely exist as catalog content;
- integrate the approved catalog at the authoritative bootstrap/acquisition boundary.
