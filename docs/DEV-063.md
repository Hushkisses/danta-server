# DEV-063 — Terrain / battlefield capacity

Status: COMPLETE — Windows automated tests/build and Paper boot verified

## Design basis
Design v0.3 requires terrain and battlefield width/capacity to matter in automatic combat. Terrain should create unit-role advantages/disadvantages, and narrow terrain should prevent a larger force from converting every soldier into simultaneous combat power. The design does not fix a final terrain coefficient table or exact over-capacity power formula.

## Implemented
- BattlefieldTerrain adds broad combat terrain categories: plain, forest, mountain, canyon, coastal, urban/fortified.
- BattlefieldContext carries terrain plus a positive battlefield-capacity value.
- BattlefieldCapacityPolicy calculates committed troops, reserve troops and force-utilization ratio.
- Troops above battlefield capacity are explicitly represented as reserves rather than silently discarded.
- TerrainCombatPolicy provides an explicit terrain hook while continuing to use the already-supported CombatSideInput terrain multiplier.
- No hard-coded terrain bonus/penalty table is invented.
- No arbitrary combat-power penalty is yet applied to reserves; the capacity result is exposed for later authoritative combat/balance integration.

## Scope boundary
- Exact terrain coefficients and capacity-to-effective-power formula remain balancing decisions.
- DEV-063 does not alter DEV-061 counter values.
- DEV-063 does not implement supply/isolation/retreat routes; DEV-064 owns those.
- Map-to-battlefield terrain classification is a later Paper/map integration concern.
- Fortification/building effects are not invented here.

## Automated tests
Tests cover terrain categories, full utilization below capacity, reserve creation above capacity, configured terrain multiplier passthrough, and preservation of existing resolver terrain behavior.
