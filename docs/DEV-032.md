# DEV-032 — Movement-time calculation

Status: COMPLETE — Windows build and Paper live-server verification passed

## Goal
Calculate an army movement order's effective server-runtime duration from the selected strategic edge's base travel time plus the first coarse route modifiers, without scheduling or moving the army yet.

## Implemented
- `ArmyMovementTimeService`: validates an existing MOVE order against the current army and strategic edge, then calculates effective movement duration.
- `ArmyMovementTime`: immutable calculation result containing base duration, effective duration, applied multiplier, and route tags.
- DEV-032 modifiers are intentionally small and data-independent:
  - `ROAD`: ×0.90
  - `MOUNTAIN_PASS`: ×1.20
  - `FOREST_PATH`: ×1.10
  - `CANYON`: ×1.15
  - `SEA_ROUTE`: ×0.90
  - `LANDING_ROUTE`: ×1.25
  - `PLAIN` and `COASTAL`: neutral for movement in this first version.
- Multiple applicable modifiers multiply together.
- Effective duration is rounded up to the next millisecond and never falls below 1 ms.
- `/danta army eta <army-id>` displays the base time, route modifier, and effective travel time in Korean.
- `/danta army move` now also previews the calculated effective travel time after accepting the pending order.

## Scope boundary
- This ticket only calculates duration. The army remains `STATIONED` and the order remains `PENDING`.
- DEV-033 will convert this duration into a RuntimeScheduler reservation, persist movement state, set `MOVING`, and complete arrival/restart recovery.
- Commander, research, supply-load, road-development, and other domain modifiers are not yet represented by the current Army model, so they are not guessed into DEV-032. They can be layered onto this calculator when those authoritative states exist.

## Automated checks added
`Dev032ArmyMovementTimeTest` covers:
- base edge time with no modifying tags
- road reduction
- mountain-pass increase
- combined route modifiers
- rejection when the order route no longer matches the army location or referenced edge
