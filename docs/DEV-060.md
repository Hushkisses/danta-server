# DEV-060 — CombatResolver v1 staged pipeline

Status: COMPLETE — Windows automated tests/build and Paper boot verified

## Goal
Replace the single-step conceptual shape of automatic combat with the design v0.3 logical phase pipeline while preserving the already-verified DEV-041 baseline until each phase receives its authoritative mechanics.

Phase order:
1. opening
2. frontline
3. backline
4. mobile
5. morale
6. retreat / pursuit

## Implemented
- CombatPhase defines the six design phases in fixed order.
- CombatPhaseResult records per-phase powers and multipliers for later diagnostics/reporting.
- CombatV1Result returns the final CombatResult plus the ordered phase trace.
- CombatResolverV1 reuses the existing CombatResolver baseline rather than duplicating DEV-041 power/counter rules.
- DEV-060 phase hooks are intentionally neutral x1.0. This means current combat outcomes remain unchanged until DEV-061~064 add their owned mechanics.
- Core unit tests verify phase order, v0 regression compatibility, and draw preservation.

## Scope boundary
DEV-060 establishes the staged architecture only. It does not prematurely implement:
- DEV-061 counter/frontline/backline/mobile mechanics;
- DEV-062 morale/retreat/pursuit mechanics;
- DEV-063 terrain/battlefield-capacity mechanics;
- DEV-064 supply/isolation/retreat-route mechanics;
- DEV-065 repeated simulation or DEV-066 CSV reporting.

No new final balance numbers are introduced.
