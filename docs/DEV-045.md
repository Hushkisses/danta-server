# DEV-045 — Combat report v0

Status: COMPLETE — live Paper combat-report output verified

## Source requirement
Execution plan v1.0 defines DEV-045 completion as displaying combat victory/defeat and losses.

## Implemented
- CombatReport is an immutable projection of the existing CombatResolution.
- Report includes both sides' outcome, initial troops, losses, and remaining troops.
- CombatReportFormatter provides Korean player-facing output: 승리 / 패배 / 무승부, 전투 전 / 손실 / 잔존.
- Internal CombatOutcome enum values remain English.
- Tests verify the 1000 infantry vs 1000 spearmen example renders red 승리/손실 100/잔존 900 and blue 패배/손실 250/잔존 750.
- Tests also verify DRAW is exposed as 무승부 and internal enum names do not leak.

## Scope boundary
- The execution plan only requires victory/defeat and loss display here, so no battle-history DB, GUI, broadcast, Discord, or mail system is invented.
- This core formatter is ready for the later Paper combat trigger to send to players.
- Added admin-only `/danta combat test` as a live Paper verification path. It runs the real resolver + loss policy + report formatter for the fixed 1000 infantry vs 1000 spearmen case.

## Windows verification
1. Stop Paper and pull main.
2. Run dev-server\\quick-deploy.bat; DEV-045 tests and build must pass.
3. Start dev-server\\start-dev.bat.
4. Confirm normal Danta boot and /danta db status = 정상.
5. Run `/danta combat test` from the server console or an authorized player.
6. Expected report: `[전투 보고서]`, `red: 승리 | 전투 전 1000 | 손실 100 | 잔존 900`, `blue: 패배 | 전투 전 1000 | 손실 250 | 잔존 750`.

## Verification result
The representative confirmed on 2026-09-15 that `/danta combat test` displayed the expected Korean victory/loss report on the live Paper server.
