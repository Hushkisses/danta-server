# DEV-MAP-003 멀티월드·탐험가 길드 설계

## 목적

단타 서버의 본게임 전략 월드와 Minecraft 본연의 생존·탐험 플레이를 분리한다.

- **전략 본토 월드**: 평지 기반 제작형 월드. 국가·영토·거점·전쟁·시설·전략지형의 무대.
- **야생 월드**: 일반 자연 생성 월드. 개인의 탐험·광질·벌목·농사·구조물 탐색의 무대.
- 두 월드 이동은 아무 곳에서나 가능한 `/warp`가 아니라 **본토의 중립 시설 `탐험가 길드`와 야생의 귀환 거점**을 통해서만 이루어진다.

## 핵심 경제 원칙

Minecraft 인벤토리 아이템과 국가 전략자원은 서로 다른 경제 계층이다.

- 야생에서 획득한 철괴·금괴·목재·농산물 등은 **개인 아이템**이다.
- 이 아이템은 국가 `StrategicResourceStockpile`의 IRON/FOOD/WOOD/GOLD 등으로 자동 변환되지 않는다.
- 국가 경제의 주 생산원은 기존 전략 거점·시설·EconomyTick 시스템이다.
- 개인의 야생 활동이 국가 경제를 대체할 수 없게 한다.
- 향후 탐험가 길드 납품 시스템을 추가할 수 있으나, 국가 전략경제에 주는 영향은 작고 조정 가능한 별도 정책으로 둔다. DEV-MAP-003에서는 납품 시스템을 구현하지 않는다.

## 월드 구조

### 1. 전략 본토

개발용 월드 이름은 `danta_main`을 기본값으로 한다.

- `WorldType.FLAT` 기반으로 생성한다.
- 자연 광석 채굴을 국가 경제 공급원으로 사용하지 않는다.
- 산맥·강·숲·협곡·도로 같은 전략 지형은 이후 지형 타일/구조물 배치 파이프라인으로 만든다.
- 수도·시장·요새·탐험가 길드 등 게임 구조물은 자동 건축 또는 NBT/structure asset으로 배치한다.
- 기존 `dev-test-map.yml`의 좌표·거점 정의는 당장 폐기하지 않는다. DEV-MAP-003에서는 새 월드 기반을 추가하고 기존 개발맵을 깨뜨리지 않는다.

### 2. 야생

개발용 월드 이름은 `danta_wild`를 기본값으로 한다.

- 일반 Minecraft 자연 생성 환경을 사용한다.
- 광질·벌목·농사·탐험·자연 구조물 탐색을 허용한다.
- 국가 전략 거점·국가 소유권·공성전 좌표는 두지 않는다.
- 월드보더 크기, 야생 초기화 주기, 시즌 중 추가 개방 여부는 최종 밸런스 미확정 사항이다. DEV-MAP-003에서는 설정값으로 분리하되 임의의 최종 수치를 확정하지 않는다.

## 탐험가 길드 이동 모델

### 본토 → 야생

1. 플레이어가 본토의 `탐험가 길드` 이동 지점에 접근하거나 상호작용한다.
2. 서버가 현재 월드와 위치가 허용된 길드 게이트인지 검증한다.
3. 야생 월드의 안전한 출발 거점으로 이동시킨다.
4. 플레이어에게 한글 안내 메시지를 표시한다.

### 야생 → 본토

1. 플레이어가 야생의 `귀환 거점`을 사용한다.
2. 서버가 허용된 귀환 게이트인지 검증한다.
3. 본토 탐험가 길드 귀환 지점으로 이동시킨다.
4. 플레이어에게 한글 안내 메시지를 표시한다.

일반 플레이어가 임의의 좌표에서 명령만으로 두 월드를 오가는 기능은 제공하지 않는다. 개발·운영 검증용 관리자 명령은 허용한다.

## 컴포넌트 경계

### `WorldRole`

월드의 역할을 `STRATEGIC_MAIN`, `WILDERNESS`로 구분한다. 내부 enum은 영어를 사용하고 플레이어 출력만 한글화한다.

### `DantaWorldConfig`

월드 이름과 개발용 게이트 위치를 담는 구성 객체다. 초기에는 코드 기본값을 제공하되 이후 YAML 설정으로 이동하기 쉬운 구조를 사용한다.

### `DantaWorldService`

Paper/Bukkit 월드 생성과 조회를 담당한다.

- 전략 본토 평지월드 생성
- 야생 자연월드 생성
- 기존 월드가 있으면 재생성하지 않고 로드
- 월드 역할 조회

월드 생성/로드는 서버 시작 시 메인 스레드에서 수행한다. DB 작업은 포함하지 않는다.

### `ExplorerGuildTravelService`

플레이어의 월드 간 이동 규칙만 담당한다.

- 본토 길드 게이트 → 야생 출발지
- 야생 귀환 게이트 → 본토 길드
- 허용되지 않은 월드/게이트 이동 거부
- 플레이어 출력은 한글

국가 전략자원 변환, 납품, 경제 보상은 담당하지 않는다.

### `ExplorerGuildBuilder`

본토에 작은 탐험가 길드 건물과 야생의 귀환 거점을 자동 생성한다. DEV-112A 대요새 생성기와 같은 명시적 관리자 설치 방식으로 시작한다.

- 길드 건물은 탐험/원정 느낌의 목재·석재 구조
- 출발 게이트와 귀환 지점을 눈에 띄게 표시
- 실제 포탈 블록 차원 이동에 의존하지 않고 서버가 지정 좌표를 이동시킨다.

## 초기 상호작용 방식

첫 구현은 안정성과 검증 편의를 위해 **관리자 설치 + 플레이어 상호작용 블록** 방식으로 한다.

- 본토 길드의 지정 블록을 우클릭하면 야생 이동
- 야생 귀환 거점의 지정 블록을 우클릭하면 본토 귀환
- 별도 명령은 관리자 검증용으로만 제공

압력판/포탈 진입 감지는 추후 UX 개선으로 바꿀 수 있지만 DEV-MAP-003의 필수 범위는 아니다.

## 기존 시스템과의 관계

- `GameState`, 국가·거점·전략자원 시스템은 본토 전략게임의 권위 상태를 계속 담당한다.
- 야생 아이템은 Bukkit 인벤토리 아이템으로만 존재하며 `StrategicResourceStockpile`을 변경하지 않는다.
- 전략 거점 생산은 기존 `EconomyTickService`/`StrategicPointProductionService` 경로를 유지한다.
- 기존 `dev-test-map.yml`, `MapStructurePlacer`, `CanyonFortressBuilder`를 삭제하지 않는다.
- 향후 지형 타일 생성기는 전략 본토 월드를 대상으로 별도 DEV-MAP-004 계열로 확장한다.

## 오류 처리

- 월드 생성 실패: 서버 콘솔에 기술 로그를 남기고 해당 이동 기능을 비활성화한다.
- 플레이어가 잘못된 게이트를 사용할 경우: 구체적인 한글 거부 사유를 출력한다.
- 목적 월드가 로드되지 않은 경우: 이동하지 않고 한글 오류를 표시한다.
- 안전한 목적 좌표를 찾지 못한 경우: 이동하지 않는다. 임의로 위험 좌표에 순간이동시키지 않는다.

## 테스트 전략

- core 도메인 로직을 억지로 만들지 않고 Paper 월드 기능은 paper-plugin 테스트/실서버 검증 중심으로 한다.
- 월드 역할 매핑과 이동 허용 판정은 순수 객체로 분리해 JUnit 테스트 가능하게 한다.
- Windows 검증은 `quick-deploy.bat` 성공 후 Paper 부팅, 두 월드 존재 확인, 길드 건축, 양방향 이동, 인벤토리 유지, 국가 전략자원 불변을 확인한다.

## 이번 범위에서 하지 않는 것

- 야생 자원 → 국가 전략자원 직접 변환
- 탐험가 길드 납품/퀘스트/상점
- 야생 월드 자동 리셋
- 최종 월드보더 크기 확정
- 최종 지형 타일 세트
- 모든 수도/마을/요새의 최종 건축물
- Discord 연동

이 항목들은 멀티월드 기반 검증 후 별도 DEV로 추가한다.
