# DEV-065 — Repeated combat simulation

Status: COMPLETE — Windows automated tests/build and Paper boot verified

## Goal
Provide the execution-plan repeated-combat harness before CSV export/balance reporting.

## Implemented
- RepeatedCombatSimulator runs a CombatScenario an arbitrary positive number of times through CombatResolver v1.
- CombatSimulationSummary aggregates:
  - first-side wins;
  - second-side wins;
  - draws;
  - win/draw rates;
  - average first/second casualties using the existing provisional DEV-042 loss policy.
- combat-simulator now accepts an optional run-count argument and defaults to 1,000 runs.
- Existing deterministic scenario set remains the regression baseline.

## Determinism decision
CombatResolver v1 currently contains no authoritative random component. DEV-065 therefore does not inject artificial randomness merely to create non-trivial win-rate distributions. Repeated identical scenarios correctly produce 0% or 100% deterministic outcomes (or 100% draws). The harness is ready for later stochastic mechanics if the design explicitly introduces them.

## Scope boundary
- CSV output is DEV-066.
- No random variance coefficient is invented.
- No DEV-063/064 provisional flags are converted into unfixed percentage penalties.
- Existing DEV-042 casualty percentages remain provisional.

## Automated tests
Tests cover 1,000-run winning aggregation, repeated draws, invalid run counts, and regression of all fixed DEV-042 scenarios through CombatResolver v1.
