# DEV-086 — National doctrine slots 2 → max 3

Status: IMPLEMENTED — Windows automated verification pending.

## Source requirement
Design v0.3 defines national doctrine capacity rather than one doctrine per field: baseline 2 slots, later condition expands to max 3, freely allocated among military/industry/administration/magic. Doctrine change is allowed but has high gold cost and long reorganization time; the old effect is inactive during reorganization. The execution plan ticket DEV-086 is specifically “교리 슬롯 2→최대3”.

## Implemented scope
- Per-nation doctrineSlots defaults to 2 and accepts only 2..3.
- Doctrine selections occupy national slots independent of field, so multiple fields may be mixed freely.
- Selection requires a completed TIER_4 ResearchDefinition with doctrineKey.
- Duplicate doctrine selection and capacity overflow are rejected.
- Snapshot schema v15 persists doctrine capacity and selections; v14 research snapshots restore as 2 empty doctrine slots.
- Core JUnit coverage added.

## Deliberately not invented
- The exact later-game condition that unlocks slot 3 is not fixed by v0.3, so DEV-086 exposes capacity state but does not invent an unlock trigger.
- Exact doctrine catalog/effects remain DEV-088/content work.
- Exact doctrine-change gold cost and reorganization duration are not specified. Therefore no fake balance values or instantaneous player-facing replacement flow is introduced here. A later ticket/content decision must define those values before change/reorganization is wired as gameplay.
