# DEV-043 — NPC basic garrison

Status: COMPLETE — Windows build/test and Paper boot verification passed

## Goal
Introduce the minimum NPC strategic-point garrison domain required before combat can flow into occupation.

## Implemented
- GarrisonState is keyed by strategic point and stores controller plus troop count.
- GarrisonController distinguishes NPC and NATION without inventing a fake nation ID for neutral NPC defenders.
- GarrisonService validates that the strategic point exists and prevents duplicate point garrisons.
- GameState is the authoritative in-memory holder for point garrisons, matching the project's state architecture.
- Core tests cover NPC creation, missing-point rejection, duplicate rejection, and controller semantics.

## Intentional scope boundary
- This ticket does not yet persist garrisons in Snapshot. Persistence is deferred until DEV-044 establishes the combat-to-occupation lifecycle so the snapshot shape is not churned twice.
- No fixed NPC troop-count balance is declared here; callers provide the count.
- No automatic spawning on every point is added.
- Garrison troop composition remains a single count for the minimum model; full composition/battle integration follows later combat work.
- No Paper command/UI is added for this pure domain ticket.
