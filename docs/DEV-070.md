# DEV-070 — General F-S + Lv1-10

Status: COMPLETE — Windows automated tests/build and Paper boot verified

## Design basis
Design v0.3 defines generals as a core combat-growth axis with:
- grades F through S;
- levels 1 through 10;
- future stat axes including command, martial, intelligence and politics;
- troop-type synergy, equipment, traits and morale/pursuit effects in later work.

The execution plan assigns only the grade/level baseline to DEV-070. DEV-071+ owns stat values and combat modifiers.

## Implemented
- GeneralGrade authoritative ladder: F/E/D/C/B/A/S.
- GeneralState aggregate with generalId, ownerNationId, grade and level.
- Level is strictly constrained to 1..10.
- Controlled levelUp stops at Lv10.
- GeneralService validates owner nation and inserts through GameState.
- GameState now stores generals by ID with duplicate protection and clear/list/lookup operations.
- No combat multiplier is invented. Existing CombatSideInput commanderMultiplier remains untouched until DEV-071+ defines authoritative mapping.

## Persistence boundary
DEV-070 establishes the in-memory domain baseline only. The execution-plan ticket itself does not specify snapshot persistence. General snapshot/schema integration should be added with the ticket that first makes generals persistent player-owned season state, while preserving legacy snapshot compatibility.

## Automated tests
Tests cover grade order, level boundaries, max-level behavior, nation ownership and duplicate IDs.
