# DEV-042 — Deterministic combat test scenarios

Status: IMPLEMENTED — awaiting Windows build/test verification

## Goal
Lock DEV-041's deterministic combat behavior with fixed expected scenarios before casualty and terrain layers are added.

## Implemented
- CombatScenario immutable expected-result model.
- DeterministicCombatScenarios fixed baseline suite.
- Six scenarios:
  1. equal infantry vs infantry -> draw at 1000 / 1000 power;
  2. infantry vs spearmen -> infantry 1250 / spearmen 1000;
  3. spearmen vs cavalry -> spearmen 1250 / cavalry 1000;
  4. cavalry vs archers -> cavalry 1250 / archers 1000;
  5. archers vs infantry -> archers 1250 / infantry 1000;
  6. 1000 infantry vs 1300 spearmen -> spearmen wins 1300 / 1250, proving the +25% relation is a soft counter rather than an absolute hard counter.
- JUnit regression test runs every scenario through the real CombatResolver and checks exact expected winner/power.
- combat-simulator prints the same full scenario suite for manual inspection.

## Scope boundary
DEV-042 does not add casualty math, terrain mapping, random variance, Paper commands, or persistence. Those belong to later tickets. Keeping this baseline deterministic makes later formula changes observable.

## Windows verification
1. Stop Paper.
2. Pull main from repository root.
3. Run dev-server\\quick-deploy.bat; all DEV-042 scenario tests must pass.
4. For direct simulator verification, from repository root run the existing Gradle command for :combat-simulator:run. The six scenario lines must match the expected values documented above.

Do not mark DEV-042 COMPLETE until representative Windows verification passes.
