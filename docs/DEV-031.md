# DEV-031 — ArmyOrder / Route

Status: COMPLETE — Windows build and Paper live-server verification passed

## Goal
Accept a validated one-leg movement order from an army's current strategic point to one directly adjacent point.

## Implemented
- `ArmyRoute`: origin point, destination point, and the connecting strategic edge.
- `ArmyOrder`: order ID, army ID, `MOVE` type, route, and `PENDING` status.
- `ArmyOrderService`: authoritative validation and creation boundary for movement orders.
- `GameState`: at most one current order per army.
- `/danta army move <army-id> <destination-point-id>` issues a pending order.
- `/danta army order <army-id>` displays the current order.

## Validation rules
- The army must exist and be `STATIONED`.
- The destination strategic point must exist.
- The destination must differ from the army's current point.
- A strategic edge must directly connect the current point and destination.
- An army with a current order cannot receive another order.

## Scope boundary
- DEV-031 records intent only; it does not change army status or location.
- DEV-032 calculates effective movement duration.
- DEV-033 schedules movement, persists runtime movement state, and completes arrival.
- DEV-034 expands the one-leg route into sequential operations.
- Pending orders are deliberately memory-only until DEV-033 defines the stable persisted movement payload.

## Automated checks added
`Dev031ArmyOrderTest` covers:
- adjacent one-leg order creation and storage
- unchanged army location/status after issuing intent
- rejection of non-adjacent, same-point, and unknown destinations
- rejection of duplicate orders and non-stationed armies

## Windows live-verification checklist
1. Stop the Paper server.
2. Pull the latest `main` branch.
3. Run `dev-server\quick-deploy.bat` from the repository root.
4. Start the server with `dev-server\start-dev.bat`.
5. Confirm PostgreSQL is READY with `/danta db status`.
6. Run `/danta devmap load` if `red`, `red_capital`, `red_farm`, and edge `e01` are not already loaded.
7. Run `/danta army create dev031_red_1 red red_capital 1000`.
8. Run `/danta army move dev031_red_1 red_farm`.
9. Verify the displayed route is `red_capital -> red_farm via=e01` and status is `PENDING`.
10. Run `/danta army order dev031_red_1` and verify the same order is displayed.
11. Run `/danta army show dev031_red_1` and verify the army itself remains at `red_capital` with `STATIONED` status.
12. Run `/danta army move dev031_red_1 red_farm` again and verify it is rejected because the army already has an order.
13. Create another army with `/danta army create dev031_red_2 red red_capital 1000`.
14. Run `/danta army move dev031_red_2 central_market` and verify the non-adjacent destination is rejected.
