# DEV-061 — Counter / frontline / backline / mobile

Status: IMPLEMENTED — Windows automated verification pending

## Design basis
Design v0.3 assigns the basic troop types to frontline/ranged/mobile roles and requires automatic combat to proceed through frontline, backline and mobile phases. The existing DEV-040/041 soft-counter cycle is already verified:
- infantry > spearmen
- spearmen > cavalry
- cavalry > archers
- archers > infantry
- soft counter multiplier: x1.25

The design does not yet fix additional phase-specific numeric bonuses, so DEV-061 does not invent any.

## Implemented
- CombatPhasePolicy maps FRONTLINE troops to FRONTLINE, RANGED to BACKLINE and MOBILE to MOBILE.
- The already-existing x1.25 soft counter is now applied in the troop's logical v1 phase rather than being conceptually pre-applied before the phase pipeline.
- CombatResolverV1 still reuses DEV-041 validation/base-power calculation and removes/reapplies only its known counter contribution, avoiding duplicated combat formulas.
- Final power/winner remains regression-compatible with CombatResolver v0.
- OPENING, MORALE and RETREAT_PURSUIT remain neutral for later tickets.
- Automated tests cover infantry/frontline, archer/backline, cavalry/mobile, full v0 result compatibility and neutral later phases.

## Scope boundary
This ticket does not invent final frontline-width, ranged-support, cavalry-flanking, morale, pursuit, terrain or supply coefficients. Those belong to later design/balance work and DEV-062~064.
