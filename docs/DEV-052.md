# DEV-052 — EconomyTick

Status: COMPLETE — Windows runtime boundary/pause/restart behavior verified

## Goal
Create the fixed 30-minute economy cadence on server runtime, not wall-clock time.

## Implemented
- EconomyTickService defines one tick per 30 minutes of accumulated server runtime.
- Tick boundaries are claimed exactly once.
- A runtime jump can claim multiple crossed boundaries without scanning historical time.
- Service initialization at recovered current runtime prevents restart/downtime from replaying old ticks.
- Paper's existing RuntimeScheduler pump also pumps EconomyTick, so pause/speed semantics come from RuntimeClockService.
- Console logs each processed batch.
- Admin status command: /danta economy-tick, with Korean current runtime/next tick/count output.

## Scope boundary
- DEV-052 creates cadence only.
- DEV-053 maps owned points to actual resource production.
- DEV-054 introduces local isolated stockpiles.
- Diagnostic tick count is not persisted; later authoritative production state will be snapshot-persisted.

## Windows verification
1. Stop Paper, pull main, quick-deploy, start.
2. Run: danta economy-tick
3. Record current runtime, next tick, and processed count.
4. Run: danta runtime speed 100
5. Wait until runtime crosses the displayed next 30-minute boundary.
6. Console must log [EconomyTick] and economy-tick processed count must increase.
7. Pause runtime with the existing runtime pause command.
8. Wait several real seconds and run economy-tick twice; runtime and count must not advance while paused.
9. Resume, then optionally restore speed to 1.
10. Stop server, wait briefly, restart, and run economy-tick. Downtime must not create extra ticks.

## Verification result
The representative confirmed on 2026-09-15 that boundary processing, pause behavior, and restart/downtime behavior all worked correctly.
