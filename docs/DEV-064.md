# DEV-064 — Supply / isolation / retreat route

Status: IMPLEMENTED — Windows automated verification pending

## Design basis
Design v0.3 makes supply a core combat input: low/depleted supply lowers combat effectiveness and morale, isolation/blocked retreat increases permanent losses, and severe isolation can create surrender risk. The design also distinguishes retreat-route availability from ordinary combat power.

Existing DEV-054 already implements capital connectivity for owned strategic points, DEV-055 implements provisional army food consumption, and DEV-056 implements expedition food loading. DEV-064 does not duplicate those services.

## Implemented
- SupplyState: SUPPLIED / LOW / DEPLETED.
- RetreatRouteState: OPEN / THREATENED / BLOCKED.
- CombatLogisticsContext carries both sides' supply and retreat-route conditions.
- CombatLogisticsPolicy converts those inputs into explicit design-consequence flags:
  - low/depleted supply -> morale penalty required + combat penalty required;
  - depleted supply -> additional-loss risk;
  - blocked retreat -> isolated + additional-loss risk;
  - depleted supply + blocked retreat -> surrender risk.
- CombatLogisticsResult evaluates both sides against CombatResolver v1 output.

## Why flags instead of percentages
The source design fixes the direction of these effects but not their final numeric coefficients. DEV-064 therefore does not invent a final -X% combat modifier, morale decrement, permanent-loss percentage or surrender probability. These typed flags are reusable inputs for later balancing/simulation.

## Existing-system integration boundary
- DEV-054 SupplyConnectivityService remains the source for strategic-point capital connectivity.
- DEV-055 ArmySupplyService remains the provisional food-consumption implementation.
- DEV-056 ExpeditionSupplyService remains the expedition-food loading implementation.
- DEV-064 does not create a second supply graph or stockpile.
- Mapping live ArmyState food/connectivity into SupplyState and finding a concrete retreat edge require a battle-location/army-composition integration layer not yet present in current core combat input; this ticket establishes the reusable combat-side contract rather than fabricating that missing state.

## Automated tests
Tests cover healthy logistics, low supply, depletion, blocked retreat/isolation, severe depletion+isolation surrender risk, and asymmetric two-side evaluation.
