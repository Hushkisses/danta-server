# DEV-044 — Combat to occupation

Status: IMPLEMENTED — awaiting Windows build/test verification

## Goal
Connect a resolved battle to authoritative strategic-point ownership without bypassing DEV-023 TerritoryService.

## Implemented
- CombatOccupationService consumes CombatResolution.
- Draw or attacker defeat cannot occupy.
- A defeated defender that still has remaining troops prevents occupation.
- When the defending garrison reaches zero, the garrison is removed and ownership changes through TerritoryService with reason combat-occupation.
- Therefore the existing StrategicPointOwnershipChangedEvent path remains authoritative for downstream snapshot flush/listeners.
- Tests verify surviving defender blocks occupation, zero defender transfers ownership and emits the existing event, and draw cannot occupy.

## Scope boundary
- DEV-042's temporary 25% loser loss normally leaves survivors; DEV-044 deliberately does not invent an annihilation trigger. Later full combat rules may produce zero defenders through encirclement/pursuit/etc.
- No automatic battle trigger from movement is added in this ticket.
- No Paper command/UI is added.
- Garrison snapshot persistence remains pending until the live combat lifecycle has an authoritative Paper integration point; do not silently mutate DB from core.
