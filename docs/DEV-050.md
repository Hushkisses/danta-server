# DEV-050 — Treasury / personal-wallet separation

Status: IMPLEMENTED — awaiting Windows live/restart verification

## Source requirement
Execution plan v1.0 completion condition: treasury and personal wallet are separate, and direct mutual withdrawal restriction is verified.

Design v0.3 rules:
- personal wallet and national treasury are separate;
- personal dungeon/quest/item-trade income belongs to the personal wallet;
- point tax/tribute/strategic-resource trade/national-project income belongs to treasury;
- personal -> treasury contribution is freely allowed;
- treasury -> personal-wallet direct withdrawal is prohibited.

## Implemented
- Existing NationState.treasury remains the national treasury.
- PersonalWallet is a separate core aggregate keyed by player ID.
- GameState is authoritative for in-memory personal wallets.
- EconomyTransferService allows personal -> treasury contribution atomically within the in-memory service boundary.
- Insufficient personal balance changes neither side.
- Treasury -> personal direct withdrawal is explicitly rejected.
- Snapshot schema advances v7 -> v8 to persist personal wallets; v1-v7 remain readable with empty wallet state.
- Economy changes use an immediate asynchronous important snapshot flush; no Paper main-thread DB I/O.
- Admin verification commands:
  - /danta economy wallet-set <player-id> <amount>
  - /danta economy show <player-id> <nation-id>
  - /danta economy contribute <player-id> <nation-id> <amount>
  - /danta economy withdraw (always rejected in Korean)

## Scope boundary
- Player-to-nation membership is not authoritative yet, so DEV-050 admin verification uses explicit player/nation IDs.
- Income sources, strategic resources, production ticks, market and economy GUI belong to later tickets.
- No treasury -> personal payment workaround is introduced; future equipment/support systems must follow design rules.

## Windows verification
1. Stop Paper, pull main, run dev-server\\quick-deploy.bat.
2. Start dev-server\\start-dev.bat and confirm /danta db status = 정상.
3. Use an existing nation such as red.
4. Run: danta economy wallet-set dev050_test 1000
5. Run: danta economy show dev050_test red and record the current treasury. Personal wallet must be 1000G.
6. Run: danta economy contribute dev050_test red 300
7. Run show again: personal wallet must be 700G and treasury must have increased by exactly 300G.
8. Run: danta economy withdraw
9. It must say in Korean that direct treasury-to-personal withdrawal is not allowed; balances must remain unchanged.
10. Stop and restart the server normally.
11. Run show again. The 700G personal balance and increased treasury must survive restart.

Do not mark DEV-050 COMPLETE until contribution, prohibited reverse direction, and restart recovery all pass.
