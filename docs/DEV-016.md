# DEV-016 — PostgreSQL connection / async repository

## Goal
Implement PostgreSQL connectivity, repository-based asynchronous persistence, and graceful connection failure handling without blocking the Paper main thread.

## Implemented
- `database.properties` auto-created under `plugins/DantaServer/`.
- Database is **disabled by default** until the developer opts in.
- Dedicated virtual-thread executor performs every JDBC operation off the Paper main thread.
- PostgreSQL connection failure changes DB status to `DEGRADED`; the game plugin remains active.
- Initial schema bootstrap creates `danta_schema_meta` and `danta_kv`.
- `AsyncKeyValueRepository` is Paper-independent and proves the Repository contract.
- DEV commands:
  - `/danta db status`
  - `/danta db reconnect`
  - `/danta db ping`
  - `/danta db put <key> <value>`
  - `/danta db get <key>`
  - `/danta db delete <key>`
- PostgreSQL JDBC driver `42.7.13` is bundled inside the single Paper plugin JAR.

## Failure policy
Database failure must never disable the strategy game runtime. Persistence becomes degraded and is reported in the console and `/danta db status`. DEV-017 adds snapshot/important-flush recovery behavior.

## Manual test after PostgreSQL is installed
Edit:
`plugins/DantaServer/database.properties`

Example:
```properties
enabled=true
host=127.0.0.1
port=5432
database=danta
user=danta
password=<your password>
connectTimeoutSeconds=5
```

Restart the server and run:
```
/danta db status
/danta db ping
/danta db put hello world
/danta db get hello
```

Expected:
- status = READY
- ping = OK
- get returns `hello = world`

## Definition of done
- Project builds.
- DB I/O is never performed synchronously on Paper main thread.
- Valid PostgreSQL connection reaches READY.
- Invalid/unavailable PostgreSQL reaches DEGRADED while the server continues running.
- Repository write/read round trip succeeds.
