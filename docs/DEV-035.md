# DEV-035 — Automatic advance-stop conditions

Status: IMPLEMENTED — awaiting Windows build and Paper live-server verification

## Goal
Automatically stop a DEV-034 sequential advance when a condition requiring a new decision is reached. The execution plan names combat, major points, and supply as the target categories.

## Implemented now
- Core stop reasons: COMBAT, MAJOR_POINT, SUPPLY.
- Core ArmyAdvanceStopPolicy and decision result.
- After every queued-leg arrival, the next leg is not started until the stop policy is evaluated.
- CAPITAL and MAJOR strategic-point types stop the remaining automatic operation.
- Stopping removes the remaining operation queue and persists that cleanup through the existing important arrival snapshot.
- The development map's central_market is now typed MAJOR, matching its design role as the unique central major market and providing a live DEV-035 test target.
- Hotfix after first live test: DevMapLoader now refreshes the bundled dev-test-map.yml on startup (backing the previous external file up as dev-test-map.previous.yml), and DevMapService refreshes mutable fields of already-existing strategic points on import. This fixes stale COMMERCIAL state surviving `/danta devmap load`.
- Combat and supply stop hooks exist in core for their authoritative systems to call later.

## Intentional dependency boundary
The execution plan places the first combat system in DEV-040 through DEV-045 and supply state in DEV-055 onward. Those authoritative states do not exist yet. DEV-035 therefore does not invent fake enemy-contact or food state into Army. Major-point stopping is fully wired now; combat and supply use typed policy hooks that will be connected when those systems exist.

## Windows live verification
1. Stop Paper, pull main, quick-deploy, and start the existing dev server.
2. Confirm DB status is 정상. On startup the bundled dev map file is refreshed; run /danta devmap load so the existing central_market aggregate is updated to MAJOR.
3. Create a fresh red army at red_capital and set runtime speed 100.
4. Run: /danta army queue <army-id> red_farm west_gate central_market canyon_fort
5. The army must travel red_farm -> west_gate -> central_market.
6. On arrival at central_market, console must log an ArmyAdvance stop with reason MAJOR_POINT.
7. The army must remain STATIONED at central_market and must NOT continue to canyon_fort.
8. /danta army order <army-id> must show no current order.
9. /danta army queue-show <army-id> must show no registered sequential operation.
10. Restart the server and verify the army remains at central_market with no resurrected queue.

Do not mark DEV-035 COMPLETE until this live test passes.
