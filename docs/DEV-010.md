# DEV-010 — RuntimeClockService

## Goal
Provide the monotonic accumulated server-runtime clock that later movement, research, production and season systems will use. The clock advances only while the Paper plugin is enabled. Persistence across restarts is intentionally deferred to DEV-011.

## Implementation
- `core/runtime/RuntimeClockService`: Paper-independent, `System.nanoTime()` based monotonic clock.
- `start()` / `stop()` are idempotent and synchronized.
- Paper bootstrap starts the clock on `onEnable()` and stops it on `onDisable()`.
- `/danta` shows the current process runtime as `HH:MM:SS` for manual verification.
- No Bukkit tick counter is used, so ordinary TPS fluctuation does not redefine elapsed server-open time.

## Automated tests
- advances while running
- freezes while stopped
- resumes from accumulated time
- repeated start/stop calls do not double-count

## Manual test
1. Build/deploy and restart the dev server.
2. Run `/danta`; note `Runtime`.
3. Wait about 10 seconds and run `/danta` again.
4. Runtime should increase by about 10 seconds.
5. Restart persistence is NOT expected yet; DEV-011 adds it.

## Definition of Done
DEV-010 is complete after the automated core tests pass and the Paper manual runtime-increase check passes.
