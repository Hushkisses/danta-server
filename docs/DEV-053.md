# DEV-053 — Strategic-point production

Status: COMPLETE — Windows exact production/restart persistence verified

## Source requirement
Design v0.3: one EconomyTick per 30 runtime minutes. Hourly base production: farm food 200, forestry wood 160, mine iron 120, commercial city +160G. Rare mineral and mana stone are not mass-produced by ordinary points. Formula modifiers (facility/research/damage/supply) belong to later systems.

## Implemented
- EconomyTick now applies each owned point's data-driven baseProductionPerHour.
- 30-minute tick produces half of the hourly value.
- food/wood/iron/rare_mineral/mana_stone map into the owning nation's strategic-resource stockpile.
- gold/g maps into the owning nation's treasury.
- Unowned points produce nothing.
- Existing dev-test-map already encodes v0.3 bases: farms 200 food/h, forestry 160 wood/h, mines 120 iron/h, central market 160G/h.
- Each production batch triggers async important snapshot flush.

## Scope boundary
- DEV-054 will separate isolated local stockpiles from nationally available resources.
- Facility/research/damage/supply multipliers are not invented here because their authoritative states do not yet exist.

## Windows verification
1. Stop, pull main, quick-deploy, start.
2. `danta resource show red` and `danta economy show dev050_test red`; record food/iron and treasury.
3. `danta economy-tick`; record next tick, then `danta runtime speed 100` and cross exactly one 30-minute boundary.
4. Red owns red_farm and red_mine in dev-test-map, so one tick must add +100 food and +60 iron. Other resource values must not change from these two points.
5. Treasury must not gain market income because central_market is unowned in the source test map.
6. Restore runtime speed to 1 if desired.
7. Restart and verify the produced values persist.
