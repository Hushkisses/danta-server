# DEV-074 — General injury / recovery

Status: IMPLEMENTED — Windows automated verification pending

## Source basis
Design v0.3 states:
- permanent death is not the normal result of ordinary combat;
- generals may become injured or severely injured;
- recovery requires time.
Execution plan v1.0 assigns DEV-074 to injury/recovery.

## Implemented
- GeneralHealthStatus: HEALTHY / INJURED / SEVERELY_INJURED.
- GeneralRecoveryState stores injury runtime and recovery-ready runtime.
- GeneralState exposes health/recovery state.
- GeneralRecoveryService applies injury and completes recovery only after the runtime deadline.
- Recovery time is based on server runtime values supplied by the caller, so offline wall-clock time is not introduced.

## Deliberately unresolved
Design v0.3 does not fix exact injury/recovery durations or injury probabilities. DEV-074 therefore does not invent:
- injured duration;
- severely injured duration;
- combat injury probability;
- modifiers by grade/stat/equipment;
- whether injured generals can command at reduced effectiveness or are completely unavailable.

Those remain explicit balance/rule items.

## Source-alignment correction included before DEV-074
A source re-check found two earlier implementation mistakes:
- design v0.3 grade ladder is F/D/C/B/A/S (no E);
- design v0.3 stats are 통솔/무력/지략/병참, not 지력/정치.
The core enums/value object and their tests were corrected before advancing.

## Persistence boundary
General persistence remains an open item. Recovery state must be included when general snapshot persistence is introduced, using runtime timestamps and legacy-compatible decoding.
